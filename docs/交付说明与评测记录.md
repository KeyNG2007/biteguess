# 美食猜猜看：交付说明与评测记录

本文供项目审核者了解实现范围、核对实验依据并复现评测。所有指标对应仓库中的报告，未完成的验证明确列为局限。

## 1. 项目目标

项目对同一张食物图片运行两条独立路线：

- 传统视觉路线：YOLO11n 五类目标检测模型，输出类别、框、置信度和区域数量。
- 多模态路线：DeepSeek `deepseek-flash`，输出允许类别、数量、未知食物和文字描述。

页面使用 FastAPI 提供上传和结果展示，并列出两条路线的耗时，便于比较模型能力和工程取舍。SAM2.1 tiny 提供独立的点提示、真实框提示和 YOLO 框提示实验，用于验证检测框作为分割提示的流程；该实验尚未集成上传页面。

## 2. 数据和范围

检测数据来自 UEC FOOD 100，仅使用五个粗粒度类别：米饭料理、面食、饺子、披萨、沙拉。原始标注是食物区域框；“数量”表示标注区域数，不表示盘中每一只饺子或每一根面条。像素去重后共有 2,327 张图，划分为训练 1,627、验证 350、测试 350。

图片、模型权重、API 密钥和运行环境不提交到 Git。数据集按官方非商业研究用途使用，仓库只保留转换脚本、配置、报告和启动说明。

## 3. 训练结果

YOLO11n 在 CPU 上使用 `imgsz=320`、`batch=4`、`epochs=10`、`seed=42` 完成基线训练，耗时约 22 分 37 秒。验证集结果：Precision 0.7907、Recall 0.8009、mAP50 0.8053、mAP50-95 0.5657。最终权重位于本地 `models/yolo_runs/baseline_10epochs/weights/best.pt`。

## 4. 固定小样本对比

评测协议和原始结果位于 `reports/comparison`。从测试集固定抽取 10 张图，每个支持类别至少出现一次；两条路线使用同一张预处理图。结果如下：

| 指标 | YOLO | DeepSeek |
| --- | ---: | ---: |
| 成功处理 | 10/10 | 10/10 |
| 类别集合完全一致 | 0.80 | 0.80 |
| 平均区域数量绝对误差 | 0.50 | 0.40 |
| 平均耗时 | 0.397 秒 | 1.614 秒 |

该样本只有 10 张，不能外推为全数据集准确率。标注只覆盖五类选定类别，图片中的汤、肉菜等不在评测真值中，因此不能用这份结果评价 `unknown_present`。评测也没有像素级分割真值，不能报告 SAM 分割准确率。

“类别集合完全一致”要求预测类别集合与标注类别集合相同；数量误差为各类别预测区域数量与标注数量之差的绝对值之和，再对图片取平均。该对比没有评价边界框定位质量，YOLO 的定位指标单独见验证集 mAP。

YOLO 平均耗时包含首次加载及排队，首图耗时为 3.334 秒；DeepSeek 耗时包含网络请求。两者不能直接解释为纯模型计算速度。本次 DeepSeek 请求累计使用 4,055 tokens。

## 5. 失败案例与解释

- 披萨样例中 YOLO 同时给出一个 0.855 的披萨框和一个 0.252 的饺子框。肉眼检查图片只有披萨，属于低置信度类别误检；提高阈值或做类别后处理可以降低这类误报，但可能牺牲召回率。
- “饺子+沙拉”样例还出现汤和肉菜等其他食物。选定类别标注只记录了饺子和沙拉；两个模型都报告米饭，但肉眼无法确认肉菜下是否有米饭。原始评分仍按已有标注保留，不把此案例解释为已证实的米饭误检或漏标。它说明复杂菜品需要结合完整标注做人工复核。
- 一张面食样例的多模态结果把一个标注区域描述为两碗面，按标注计算类别正确、数量误差为 1。该案例尚未完成人工核验，不直接认定为幻觉；语义数量与区域标注的口径也需要对齐。

以上案例说明，五类封闭检测、开放场景描述和区域计数具有不同的任务边界。当前结果支持流程可运行的结论，尚不足以证明系统对任意食物图片均可靠。

## 6. 审核与复现入口

安装和启动步骤见仓库 README。运行网页需要本地五类权重 `models/yolo_runs/baseline_10epochs/weights/best.pt`；启用 DeepSeek 还需要按 `.env.example` 配置有效 API 密钥。仓库不包含权重，因此仅克隆代码不能直接进行本地检测。

审核者可通过以下文件核对各阶段实现及实验依据：

| 内容 | 实现或证据 |
| --- | --- |
| 数据转换与划分 | `scripts/prepare_uecfood100.py`、`reports/detection_data_check.json` |
| YOLO 训练与验证指标 | `scripts/train_yolo_baseline.py`、`reports/yolo_baseline.json` |
| 双模型接口与页面 | `src/app.py`、`src/index.html` |
| 对比评测 | `scripts/evaluate_comparison.py`、`reports/comparison/protocol.json`、`results.json`、`summary.json` |
| SAM 提示实验 | `scripts/demo_sam.py`、`reports/sam_demo/result.json` |

重新运行对比评测需要转换后的测试集、五类权重和 API 配置，会产生 API 调用费用。评测脚本拒绝覆盖已有结果；如需复现，应先另行保存原始报告，再在独立副本中运行：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_comparison
```

## 7. SAM 实验与验证局限

三种提示在同一张验证图上均生成一个掩膜，单次 CPU 耗时约 2.1 秒。YOLO 框提示的可视化选中了锅体周围区域，未正确选中米饭。该案例作为分割失败现象保留，生成掩膜不等于正确分割，SAM 分数也不等于食物类别置信度。

数据划分避免了像素内容完全重复的图片跨集合，但尚未全面排查近似重复或同一场景图片。双模型对比仅覆盖固定 10 张已知类别图片，尚未进行完整测试集评估、未知食物拒识评估或阈值调优。运行视频不包含在本次文档提交中。
